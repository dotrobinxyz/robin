BAND-1 — the agent banding standard.

Revocable, verifiable on-chain identity for software agents on Robinhood Chain, built on ENS-standard .robin names. Know your agent.

1. The model.

Agents are transacting on Robinhood Chain — trading, holding funds, talking to venues. A wallet address says nothing about what an agent is or who answers for it. BAND-1 gives every agent an identity that can be verified by anyone and revoked by its operator:

sniper1.pons.robin  → one subname per agent, under the operator's name

  • The operator holds a wrapped second-level name (pons.robin) and mints one subname per agent.
  • Subnames are minted to the operator, not the agent. The agent's account goes in the addr record. This is the load-bearing choice: the operator keeps record authority and can revoke — reclaim the subname and clear its records — in one transaction. An identity that cannot be taken away is a liability, not a credential.
  • Names expire. Renewal is the operator's heartbeat; an abandoned fleet stops verifying by itself.

2. Records.

3. Verification.

A verifier — a venue, a launchpad's bot gate, a counterparty agent — checks:

  1. Normalize the name (ENSIP-15) and compute its namehash.
  2. The node is registered (registry entry, or provable records).
  3. The root second-level name is unexpired.
  4. An addr record is set — and matches the account you're facing.
  5. Optional, strongest signal: the address's reverse record points back at the name (primaryMatch).
  6. Walk the operator chain — every ancestor up to the 2LD. This is who can revoke the agent; trust the chain, not the label.
  7. Read the capability card and apply your own policy.

All of it is one call against the public index (or your own — ponder start self-hosts it):

curl -s https://api.dotrobin.xyz/verify/sniper1.pons.robin

{
  "verified": true,
  "checks": { "registered": true, "rootActive": true,
              "addressSet": true, "primaryMatch": false },
  "address": "0x…",            // the agent's account
  "operator": { "name": "pons.robin", "owner": "0x…" },
  "operatorChain": [ … ],       // who can revoke, in order
  "agent": { "capabilities": ["swap","quote"], "model": "…", … }
}

The directory of every banded agent: GET https://api.dotrobin.xyz/agents (filter with ?operator=pons.robin).

4. Freshness.

Verification is a statement about now: names expire and agents get revoked. Never cache a verdict longer than 60 seconds for anything that moves value. The API stamps every response with asOf.

5. Security considerations.

  • Records are self-attested. A capability card is a claim by the operator, not an audit. What BAND-1 proves is accountability — which operator answers for this agent — not competence.
  • Trust the chain, not the label. sniper1.pons.robin means only that the holder of pons.robin vouches for it. Decide which operators you trust; the label text proves nothing.
  • For value transfer, require primaryMatch. The reverse-record round trip binds account and name in both directions.
  • Expiry is a feature. A verifier rejecting expired roots is the system working as designed.
  • Emancipated subnames (fuse PARENT_CANNOT_CONTROL) cannot be revoked by the operator — verifiers may treat them as self-sovereign agents and apply stricter policy.

6. Versioning.

BAND-1 is additive: new agent.* keys may be defined without breaking verifiers. Breaking changes get a new number. Propose changes: github.com/dotrobinxyz/robin or hello@dotrobin.xyz.
